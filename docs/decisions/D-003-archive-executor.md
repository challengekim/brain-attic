## 정해야 하는 것

d(버릴 후보) 카드는 승인해도 attic 이 볼트 노트를 옮기지 않고 `_attic/approved/<id>.prompt.md` 지시문만 썼습니다(attic 은 `_attic/` 밖에는 쓰지 않는다는 원칙). 2026-11-09 기준 승인된 보관 카드 21건이 지시문으로만 남아 있습니다.

2026-11-09 변경(PR 이 결정의 근거)으로 b·d 카드는 기본으로 꺼졌습니다(`review.autoCards`). 그래서 지시문이 더 쌓이지는 않습니다. 남은 것은 두 가지입니다.

## 선택지

1. **그대로 둔다(추천).** d 는 승인 시트에 목록으로만 보이고, 옮길지는 태우님이 볼트에서 직접 한다. 이미 승인된 21건의 지시문도 그대로 둔다.
2. **보관 실행기를 만든다.** 화이트리스트 op 로 «볼트 안 보관 폴더로 이동» 을 추가한다. `_attic/` 밖에 쓰는 첫 기능이라 dry-run 목록 → 소수(3건) 실제 이동 검증 → 되돌리기 기록을 거친 뒤 켠다. 그 뒤 d 카드를 다시 켠다.

## 근거

- 결정필요관리 창구 실측(2026-11-09): b/d 승인 지시문 32개가 쌓였고 아무도 실행하지 않았다.
- 지시: «b/d 가 실제로 실행되게 하거나, 실행 안 할 거면 b/d 를 제안하지 않는다.» 이번 변경은 후자를 택했다.

## 결정

태우님 결정(2026-11-09 22:40, 결정필요관리 창구 경유): «실제로 옮기는 기능을 만들어서 보관처리해». 선택지 2.

1. 승인된 보관(d) 카드는 `attic apply` 가 노트를 볼트 안 `90_Archive/<원래 경로>` 로 옮긴다(화이트리스트 op `archive_note`). 지시문(`_attic/approved/*.prompt.md`)은 더 만들지 않는다.
2. 옮기기만 하고 노트를 고치거나 지우지 않는다. 덮어쓰지 않고(하드 링크 후 원래 자리 제거), 앞뒤 해시를 비교하고, 원장 `_attic/archive/ledger.json` 에 남겨 `attic archive undo` 로 되돌린다.
3. 다른 노트가 경로 링크로 가리키는 노트, 같은 이름의 노트가 또 있는 노트는 옮기지 않는다.
4. 실행 순서: dry-run 목록 → 3건 실제 이동·검증 → 나머지.
5. d 카드(`review.autoCards`)를 다시 켤지는 실행기가 검증된 뒤 태우님께 묻는다. 지금은 끈 채로 둔다.
